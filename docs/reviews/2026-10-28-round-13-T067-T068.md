The '\n' path, end to end:

- `callMessage` → the vdom's `setAttribute('data-arg', …)`. There is no HTML parsing and no dataset write. The value reads back intact through `getAttribute`/`dataset` in real Chromium; `outerHTML` holds a literal LF, which the HTML parser would keep if it were ever re-parsed.
- The delegated click handler reads `getAttribute('data-arg')`.
- `sendMessage` → `normaliseMessage`, which trims the ends only.
- `RoomClient.send`, or `queue()` while offline: it stores the object unchanged and `flushPending` sends it with `JSON.stringify`.
- Real-Chromium probe (scratchpad probe2.mjs, `page.tap`): live taps sent `{"t":"msg","text":"GO LOW\nEXIT"}` and `"GO TOP\nENTRY"`. Taps made before the socket opened were queued, then flushed after the replay in order, with the newline intact, and a tap after a re-render still carried it.
