verdict: approve with nits

findings:

- [nit] apps/spotter/src/main.ts:546 — `pageshow` also fires on a normal first load (persisted=false). With a stored session, `join()` → `client.connect()` has already run during module execution, so `pageshow` arrives while that socket is still connecting or not yet replayed. `connect(sameUrl)` then tears it down and opens a second socket. Scenario: reload the PWA on LTE → one aborted handshake and roughly one extra RTT before the console is live. If the first hello already landed, the driver's S also flickers. — fix: `window.addEventListener('pageshow', (e) => { if (e.persisted) resumeLink(); })`. bfcache restore is the only case `visibilitychange` doesn't already cover.
- [nit] apps/spotter/src/main.ts:540 — the page doesn't drop its socket when it goes hidden. On Android Chrome a tab hidden for more than 5 min gets intensive timer throttling (wake-ups at most once a minute), so pings stop. The relay then reaps the spotter (correct per AC-7), and the throttled reconnect timer rejoins it about once a minute. Each rejoin lasts 6–9 s before the next reap. Scenario: spotter switches to another app mid-session → the driver's S shows for about 9 s every minute, and each presence flip costs a state broadcast and a HUD job. — fix (optional, T051 or later): on `visibilitychange` → hidden, call `client.disconnect()`, and let `resumeLink` reconnect on visible. Or accept the flapping and note it in spotter-ui.
- [nit] services/relay/src/race-room.ts:455 (logDrop at :74) — for `unknown_t` the log line includes `t` exactly as the client sent it, which can be up to about 1 KB of arbitrary client text. That is effectively a body fragment in the log, against "never with the body" (020 AC-9 / 060 R4). — fix: log `t` only for known types, or log `t.slice(0, 16)` / its length for unknown ones.
- [nit] services/relay/src/race-room.ts:292-294 — the plan's "arm on accept or reap next tick" was resolved as "reap next tick" without arming. So a never-hello socket in a room with no alarm armed (a fresh room, nobody joined) is never reaped until it closes on its own. It is harmless: there is no storage, no presence, and the TTL alarm would reap it in an idle room. The 020 Decision line ("unready sockets are reaped by the same rule"), however, reads as unconditional. auth.test.ts `alarm: null` assertions stay correct under this choice, but the commit doesn't say so as the plan asked. — fix: add one clause to the 020 Decision / skill: "reaped on the next alarm, which a lone unready socket does not arm".
- [nit] services/relay/test/validation.test.ts:124 — the wrong-role case can't fail without the new `senderRole` gate, because the reducer already ignores a driver `lane` and a spotter `ack` with an unknown msgId. Nothing asserts that drops are counted or that the log line has no body. `name=''` is tested only in the URL, not in hello. — fix: expose `output` from live-worker.ts:101 and assert one `{"ev":"drop","reason":"wrong_role"…}` / `unknown_t` / `silent_peer` line per case and that the body is absent. Add a hello with `name:''` against a URL without a name.
- [nit] services/relay/test/heartbeat.test.ts:118 — on the workerd limitation: asserting the alarm going from the 3 s tick back to the 24 h TTL does prove the reaper accounted for the never-hello socket, so I accept it. It doesn't prove the 4408 frame was sent. — fix (cheap, with the log exposure above): also assert the `silent_peer` drop line with `role:"driver"` for the lurker.
- [nit] packages/protocol/src/index.ts:75/98 — `CLIENT_MESSAGE_TYPES` and `senderRole` copy facts from `ClientMessage` and the reducer's role checks, and nothing guards against drift. A new client frame added to `isClientMessage` but not to the list would be silently ignored as `unknown_t`. — fix: add a type-level assertion `ClientMessage['t']` ≡ `ClientMessageType` in guards.test.ts, plus a reduce test that each wrong-role type is a no-op.
- [nit] packages/protocol/src/client.ts:228 — the same-URL freshness window is 2 × PING_INTERVAL_MS = 4 s, so the healthy-age margin is about 2 s minus RTT. On a bad-LTE RTT spike over about 2 s, a foreground or `online` connect replaces a healthy socket. The only cost is one reconnect, so it is acceptable. — fix (optional): use `SOCKET_SILENT_MS - PING_INTERVAL_MS` (4 s, same today) so the bound follows the silence constant, or document the trade-off.
- [nit] services/relay/src/race-room.ts:437 (and the webSocketClose/webSocketError calls to scheduleAlarm) — a hello or close moves the armed alarm LATER, to now + ALARM_TICK_MS. A socket that keeps joining or leaving faster than every 3 s therefore starves the reaper. This predates the range, but the reaper now depends on it. Realistic churn (backoff ≥ 500 ms, at most two phones) never sustains that rate, so it doesn't block. — fix (later): on join or close, pull earlier only when an alarm is already armed (`earlierAlarmAt` pattern).

hardware note (not a finding, for T051/T104): both the reaper and the existing NO LINK watchdog assume the Even Hub WebView keeps 2 s timers running with the driver's phone locked in a pocket. If iOS/Android throttles them, the driver is now reaped every ~9 s rather than merely showing NO LINK. Verify on hardware with the phone locked.

  - dropDeadSocket on a CONNECTING socket: browser `close()` doesn't throw. `ws` emits 'error', which has a no-op listener.
  - An ef8d476 drop doesn't reset `reconnectAttempt` before replay, and does after replay (so the first post-drop retry is 500 ms).
  - Visibility connect and the thawed ping tick racing each other can't open two sockets: whichever runs second finds `socket` undefined or replaced, and `connect` clears the pending reconnect.
- Glasses: a non-terminal 'closed' leaves `app.terminal` undefined (app.ts:122). `statusLine` keeps blinking `L` (NO LINK), never DISCONNECTED or LINK ERROR. The ack guard resets on non-open. The FOREGROUND_ENTER path (input.ts:172, debounced 1 s) gets the freshness check through `client.connect`. `bad_frame` isn't a terminal code in the glasses (app.ts:313) or the spotter (main.ts:185 acts only on 'auth'), so the new `bad_frame` replies on joined sockets can't strand either client. A 4408 close isn't terminal in RoomClient, so it reconnects.
- Relay against T050:

  - `isLive` (ready && !rejected) gates persistAndBroadcast and hasReadyPeer. scheduleAlarm and alarm() exclude rejected sockets.
  - Reaping runs before the TTL check and the 6 s stale clear in the same alarm, which always re-arms (except on expire).

  - The UTF-8 byte cap is checked before JSON.parse. The `raw.length` shortcut is sound because UTF-16 units ≤ UTF-8 bytes.
